# 用户企业监测口径：近7日最新动态 + 可读简报

## 背景

用户纠正过一次企业监测口径：他要的是“企业最新动态”，不是长期战略情报或90天背景线索；时间范围应缩小到近1周内新闻，整理结果要具备可读性。

## 固定口径

- 时间范围：默认近7天内公开新闻/公告/动态。
- 对象全覆盖：目标企业都要出现；无有效新闻也要说明。
- 准确性优先：宁缺毋滥，不用旧闻、无年份信息、日期不可核验信息。
- 可读性优先：推送要像领导简报，不要堆字段。

## 禁止项

一律排除：

- 招聘、校园招聘、岗位、就业信息、招聘简章、到期时间；
- 百科、公司简介、工商信息、会员单位介绍；
- 股票行情、涨停分析、研报、财报点评、公告列表/大全；
- 栏目页、列表页、泛化标题页；
- 公司成立/注册/创立/更名等历史属性日期；
- 超过7天的旧闻，或只有月日无年份且不能核验的内容。

## 推荐飞书格式

```text
📰 近7日企业最新动态 | M月D日(周X)

━━━━━━━━━━━━━━━━━━━━

🔴【重要】企业名
标题（YYYY年M月D日）
→ 1-2句话说明发生了什么、涉及哪些项目/合作方/关键数据、为什么值得关注。没有量化数据时写“公开信息未披露明确金额/产能等量化数据”。
👉 来源名：https://...

🟢【一般】企业名
近7日暂无通过核验的公开动态

━━━━━━━━━━━━━━━━━━━━
📊 近7日通过核验 N 条；已排除旧闻、招聘、百科/简介、股票行情/研报和栏目页
```

## 实施注意

- 脚本输出给 LLM 的尾部提示词也要同步改成“近7日可读版”，否则 cron 可能仍按旧字段化风格整理。
- 如果用 cron 手动触发后发现输出仍是旧提示词，检查 `~/.hermes/scripts/daily_news_search.py` 尾部硬性要求与 `cron/jobs.json` prompt 是否同时更新。
- webhook/token 不得在最终回复中泄露；只报告飞书 `code/msg` 和统计结果。
