# 用户简报与飞书推送可读性规则

## 适用场景

用于企业动态、信息监测、网页文章学习、工作简报、飞书推送、领导汇报素材等输出。

目标：不是把资料原样搬运，也不是堆字段，而是整理成“看得懂、抓得住重点、可直接转发/使用”的简报。

## 总原则

1. **先讲结论，再给依据**：读者应在前两行知道发生了什么、是否重要。
2. **少堆字段，多写自然语言**：不要机械列“来源/事项类型/核验状态”等内部字段，除非用户要求审计。
3. **有数据就写数据**：金额、产能、时间、比例、合作方、项目地点优先保留。
4. **没数据不编造**：写“公开信息未披露明确金额/产能等量化数据”。
5. **可追溯**：重要信息必须有来源或链接。
6. **宁短勿散**：每条通常 2-4 行，避免长段堆砌。

## 飞书企业动态推荐格式

```text
📰 近7日企业最新动态 | M月D日(周X)

━━━━━━━━━━━━━━━━━━━━

🔴【重要】企业名
标题（YYYY年M月D日）
→ 1-2句话说明：发生了什么、涉及哪些数据/项目/合作方、为什么值得关注。
👉 来源名：链接

🟢【一般】企业名
近7日暂无通过核验的公开动态

━━━━━━━━━━━━━━━━━━━━
📊 近7日通过核验 N 条；已排除旧闻、招聘、百科/简介、股票行情/研报和栏目页
```

## 分级口径

- 🔴【重要】：重大项目签约/开工/投产、投融资/并购/债券、重大战略合作、重大政策影响、重大经营变化。
- 🟡【关注】：市场拓展、技术创新、绿色低碳、调研交流、客户合作、区域布局等。
- 🟢【一般】：普通经营动态、轻量活动，或无有效新闻。

## 可读性检查清单

输出前自检：

- [ ] 读者能否一眼看懂发生了什么？
- [ ] 是否避免了内部字段堆砌？
- [ ] 是否写了关键数据/合作方/项目？
- [ ] 是否有来源或链接？
- [ ] 是否删除了旧闻、招聘、百科、行情、研报等噪声？
- [ ] 无动态时是否明确写“近7日暂无通过核验的公开动态”？

## 禁忌

- 不要把搜索结果标题堆成列表；
- 不要把旧闻包装成最新动态；
- 不要把招聘、百科、公司简介、股票行情、证券研报写入企业动态；
- 不要为了显得完整而编造数据或意义；
- 不要输出过长技术日志。
