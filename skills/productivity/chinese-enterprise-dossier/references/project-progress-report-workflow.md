# 客户项目进展报告工作流

## 适用场景

为某工程集团经营管理部更新/撰写重大项目进展报告，供集团领导审阅。典型触发条件：

- 客户项目取得重要里程碑（环评公示、土地整理、核准批复等）
- 需要向领导定期汇报重点客户项目跟踪情况
- 初稿已存在，需基于公开信息查询补充最新进展和数据

## 典型交付物

格式化 .docx 文档，保存至 `01_客户管理/0.客户档案/<客户集团名>/` 目录。

## 信息采集策略

### 1. 读取现有初稿
- 路径通常在 `Desktop/01_客户管理/0.客户档案/<客户名>/` 下
- 用 `read_file` 自动提取 .docx 文本

### 2. 联网搜索补充信息（多轮并行）

**第一轮 — 项目核心信息：**
```
搜索1: <客户名> <项目名> 2025 2026
搜索2: <客户名> <项目名> 进展 环评
搜索3: <客户名> <项目名> 总投资 产能 技术
```

**第二轮 — 深度阅读 & 验证：**
- 对搜索结果中详细报道类的文章用 `web_extract` 获取全文
- 重点关注：环评公示日期、中标公告、核准进展、技术路线详情
- 从行业媒体（搜狐化工、流程工业、化工在线等）提取技术细节

**第三轮 — 补充上下文：**
- 客户企业官网（了解整体实力、产业链布局、最新动态）
- 行业竞争格局（周边同期项目、竞争对手规划）
- 项目所在基地/园区规划（如曹妃甸基地2030规划目标）

### 3. 信息验证规则
- 每条关键数据标注来源：环评公示日期、中标金额、产能数据
- 多个来源交叉验证（同一数据在不同文章中出现即可信度高）
- 数据冲突时取官方公示信息（环评报告 > 行业媒体 > 自媒体）

## 文档结构模板（v4 版 — 用户偏好，经多次修订确认）

> ⚠️ 此模板是用户亲自修改4版后确定的最终结构。后续所有项目进展报告必须严格遵循此6章结构，不能再使用之前的9章模板。

```
标题：<项目名>情况报告（更新：YYYY年M月）

一、项目概况
  - 概述段落（项目定位、位置、总投资、产能、装置套数、战略意义）
  - 基本信息表（2列表格：项目/内容，行含：项目名称/建设单位/成立时间/控股关系/项目负责人/选址/总投资/用地面积/建设性质/建设周期）

二、项目主体及投资人背景
  - （一）股权结构（层层穿透至最终控制人，含前身沿革）
  - （二）某石化企业基本情况（品牌价值/荣誉、产能/配额/产业链布局、线下渠道/海外布局/研发体系）
  - （三）核心管理人员（层级关系表：控股→子公司/项目公司，列：层级/企业名称/法定代表人/职务背景）
  - 关键人备注（如创始人亲自挂帅则标注"一把手"工程）

三、<项目所在园区>环境分析
  - （一）园区定位与规划（国家级/省级背景、远期目标）
  - （二）园区优势条件（港口物流/产业集聚/公辅设施/政策支持/原料供应——用bullet list）
  - （三）项目落地意义（对产业链、区域经济的影响，引用企业高层公开讲话数据）

四、建设内容与装置清单
  - （一）装置全览（分1.炼油部分 和 2.化工部分，各一个4列表格：序号/装置名称/装置能力/备注，★标记高端新材料/进口替代品种）
  - （二）产品与技术路线（产业链上下游阐述，非纯技术说明）
  - （三）产业链协同优势（bullet list：全链条贯通/公用工程一体化/已有产能协同/下游项目衔接）

五、项目进展与里程碑时间线
  - 3列里程碑表格（时间节点/里程碑事件/备注细节），所有公开事件标注来源
  - （一）前期手续办理阶段（按年份分节，叙述式展开）
  - （二）当前阶段（含最新关键节点——如高层发布会、协议签署等）
  - （三）后续关键节点预判（bullet list，基于同类项目经验推算）

六、跟踪情况与合作建议
  - （一）已有工作基础（bullet list：高层互访时间+内容、部门拜访次数+目的、具体公司/团队跟进情况）
  - （二）业主合作意向（总体设计单位、核心装置分包意向、其他装置待定情况）
  - （三）后续跟踪建议（bullet list，每条编号+动作+时间节点+策略目的）
```

### 结构规范要点

1. **不用独立的小结章** — 与v3版不同，v4版不再设"九、小结"
2. **战略意义和竞争格局并入环境分析章** — 不单独成章，分别在"项目落地意义"和"三期"中体现
3. **时间线表格用3列**（时间节点/里程碑事件/备注细节）— 不用2列或纯列表
4. **装置表格分炼油/化工两块** — 每块独立的4列表格（序号/名称/能力/备注），不是一张大表
5. **bullet list 统一用法** — 优势条件、协同优势、后续建议等均用 bullet list，正文段落首行缩进

## python-docx 格式规范

### 页面设置
```python
section.top_margin = Cm(2.54)
section.bottom_margin = Cm(2.54)
section.left_margin = Cm(3.17)
section.right_margin = Cm(3.17)
```

### 中文字体设置（关键——否则Word中显示为默认字体）
```python
from docx.oxml.ns import qn

def add_run(paragraph, text, bold=False, size=None):
    run = paragraph.add_run(text)
    run.bold = bold
    if size: run.font.size = size
    run.font.name = '仿宋_GB2312'
    run._element.rPr.rFonts.set(qn('w:eastAsia'), '仿宋_GB2312')
    return run
```

### 样式对照表
| 元素 | 字体 | 字号 | 备注 |
|------|------|------|------|
| 文档大标题 | 无特定要求（heading 0） | 22pt | 居中加粗 |
| 副标题 | 楷体 | 16pt | 居中 |
| 一级标题(H1) | heading 1 | — | 自动 |
| 表格内容 | 仿宋_GB2312 | 10-12pt | 表头加粗居中 |
| 正文 | 仿宋_GB2312 | 14pt | 首行缩进0.74cm，1.5倍行距 |

### 表格生成
- 用 `doc.add_table(rows, cols)` + `table.style = 'Table Grid'`
- 每单元格逐 paragraph 设置 font
- 行距 `paragraph_format.line_spacing = 1.5`
- 段间距 `paragraph_format.space_after = Pt(4)`

### 时间线表格（v4版推荐格式）

用3列表格呈现项目里程碑：

| 时间节点 | 里程碑事件 | 备注/细节 |
|---------|-----------|----------|

- 第三列是关键——放来源标注、公开数据的具体数字、内部备注等细节信息
- 每行尽量写清公开/内部的数据来源

### 装置清单表格（v4版推荐格式）

炼油和化工部分各用独立表格，4列：

| 序号 | 装置名称 | 装置能力（万吨/年） | 备注 |

- 备注列放用途说明（如"龙头装置""重油加工""高端新材料★"等）
- 标★表示高端新材料/进口替代品种

## 数据源透明度规则（用户强调）

用户会要求核实每条信息的来源。必须主动做好数据溯源：

1. **每条数据标注来源** — 在正文中使用「信息来源」备注或在末尾附录「数据来源汇总表」
2. **来源分类标记**：
   - ✅ 公开可查（标注具体网址或官方文件名称）
   - ❌ 内部信息（标注"我方跟踪文档/内部记录"，不可编造成公开数据）
3. **数据差异处理**：同一项目在不同时间点可能有不同口径的数据（如2024年公示X亿、2026年发布会X亿），必须在报告中说明差异原因（"反映项目范围扩增"）
4. **不编造**：搜索不到的数据标注"未公开披露"或保持内部标注，不凭空添写
5. **追溯链完整**：用户问"数据从哪来的"时，能立即给出具体来源链接和原文段落

## 从参考文档驱动的构建模式

当用户提供一个已有的进展报告（如某一项目的v4修订版）并要求为另一个项目"按同样的结构"生成报告时：

1. **用 read_file 提取参考文档的完整结构** — 包括章节层级、表格格式、列表样式、段落间距
2. **保留参考文档的表述风格** — 如"基本情况"的段落写法、表格的列数、bullet list的用语习惯
3. **内容替换而非自由创作** — 将参考文档的结构套用到新项目的数据上，不擅自增加参考文档中没有的章节
4. **确认结构对应关系** — 如参考文档第三章是"产业基地环境分析"，新项目也要有对应章（替换为相应的园区名称），不要改成"竞争格局分析"

## 常见陷阱

1. **.docx 是 zip 格式** — 不能用 `write_file` 直接写纯文本，必须用 python-docx 库生成
2. **中文字体名称** — python-docx 中设置 `font.name = '仿宋_GB2312'` 的同时必须设置 `rFonts` 的 `eastAsia` 属性，否则 Word 中显示为宋体/等线
3. **closing tag** — 文档写完调用 `doc.save(path)` 即可，不需要手动关闭
4. **文件被锁定** — 如 Word 当前打开了该文件，save 会失败。检查后再保存
5. **⚠️ 项目进展验证** — 客户档案中列出的每个项目必须联网搜索确认最新进展，不能照搬旧资料中的状态
6. **数字精确性** — 投资额精确到小数点后一位（如345.X亿元），用地面积提供平方米和亩双单位
