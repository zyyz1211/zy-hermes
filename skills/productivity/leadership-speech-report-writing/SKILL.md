# 领导讲话知识库 → 经营建议/汇报材料

用户（某工程集团经营管理部）的知识库是 **PDF + docx 混合**（如 D:\<知识库>\集团领导讲话，约16篇讲话）。任务模式：结合领导讲话写经营建议/汇报材料，输出公文格式 docx。

## 工作流

1. **盘点知识库**：`search_files(target='files')` 列出目录。若知识库是 PDF+docx 混合，**先读最新 docx**（read_file 可直接提取 docx 文本）——docx 通常是最新材料（如 2026年中研讨班讲话），项目细节最全。
2. **批量提取 PDF**：用 pymupdf 提取全部 PDF 到 `_extracted/*.txt`，复用 `scripts/extract_pdfs.py`。提取后立即搜索关键区域/主题词。
3. **关键词检索 + 读全文上下文**：grep 命中后用 read_file 读原文段落，不要只看 grep 片段——引用必须逐条落到具体讲话和日期。
4. **撰写建议**，结构建议：
   - 总体判断（国家战略 + 集团部署依据 + 已落地经营实绩）
   - 重点经营方向（3-6条，条条有讲话出处）
   - 风险防控与保障措施
   - 结尾给出明确动作建议（专项方案/目标/督办）
5. **生成公文 docx**：复用 `templates/gongwen_docx.py`（方正小标宋标题 / 黑体一级 / 楷体二级 / 仿宋正文，A4 页边距 3.0/2.6/2.8/2.6cm，正文 14pt 首行缩进 2 字符、1.5 倍行距）。
6. **存放**：docx → 桌面 `04_汇报材料\`；生成脚本 → `09_工具脚本\`（用户硬性要求，脚本不散放桌面）。**完成后删除 `_extracted` 临时目录**，不污染知识库。

## Pitfalls（本类任务实测）

- **PDF 提取文本字符间常带空格**：如 `新签合同额****亿元`、`2026 年`。多字词组 grep（如 "新疆"）会漏检 → 先 grep 单字（"疆"）或正则 `新\s*疆` 兜底。
- **关键词在 PDF 查不到 ≠ 知识库没有**：docx 是独立文件，必须单独查（read_file 直接读 docx）。本任务中"新疆"细节全部在 2026年7月 docx 里，PDF 只有宏观表述。
- **领导讲话数字常被脱敏为 `**`**（如 `新签合同额****亿元`）：引用时如实保留 `**`，**禁止补造数字**——用户对数据准确性极敏感，明确要求不出现 AI 幻觉。
- **python 脚本 docstring 里写 Windows 路径**（`D:\<知识库>`）会触发 SyntaxWarning → docstring 用正斜杠或 raw string。
- 引用领导讲话观点时逐条标注"（来源：XXX同志XXXX年XX会议讲话）"，用户偏好**可核验出处**。

## 写作偏好（用户确认过的）

- 汇报材料只选 1-2 个典型案例，突出具体项目/数字/区域支撑，避免逐个列举、泛谈模式理念。
- 数据来源逐条注明：公开可查 vs 内部记录（领导讲话属于内部记录，标到讲话名+日期即可）。
- 结构一致性：后续同类报告与已确认的成熟版本保持章节结构一致。
