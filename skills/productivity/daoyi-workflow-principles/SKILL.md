# 用户任务执行总原则

## 适用场景

当用户提出复杂任务、自动化任务、脚本/配置修改、企业监测、飞书推送、办公材料、客户档案、周报述职、党建发言材料等任务时使用。

核心目标：减少跑偏、减少过度设计、提升可交付质量。

## 四条原则

### 1. 执行前先想清楚

复杂任务启动前，先在内部明确：

- 任务目标：用户真正要的交付物是什么？
- 范围边界：时间、对象、内容范围是什么？
- 成功标准：什么结果算完成？
- 不做什么：哪些内容不能擅自加入？
- 验证方式：如何证明已经完成？

不要把这个模板机械地发给用户；只有口径存在实质歧义、会影响结果时才提问。低风险选择直接按最合理方案执行。

### 2. 简单至上

优先用最简单、最直接的方式完成当前任务：

- 不擅自扩大任务范围；
- 不为未来假设做过度抽象；
- 不把可读材料做成数据库字段；
- 不把一次性任务做成复杂系统；
- 用户要求“最新动态”时，不扩展成长期背景情报；
- 用户要求“可读”时，不堆内部字段和技术日志。

### 3. 手术式改动

修改脚本、配置、cron、skill、profile 时只改目标相关部分：

- 不顺手重构无关代码；
- 不影响其他 cron/job/profile；
- 不把临时结论写成永久规则；
- 修改后必须验证；
- 涉及 webhook/token/API key 时不泄露具体值。

### 4. 推荐软件先验系统要求

向用户推荐第三方软件/工具/GitHub 项目前，必须先检查：
- 操作系统要求（Windows 原生 / WSL2 / macOS / Linux）
- 运行环境依赖（Python 版本、Node.js、Docker 等）
- 是否支持用户的实际平台
- 不要仅凭项目描述或名称推断兼容性，必须读 README 或文档确认
- 推荐时附上明确的下载地址和已知注意事项（如签名、UAC 弹窗等）

### 5. 目标驱动验收

复杂任务结束前必须用实际证据验证，而不是只描述：

- 文件任务：确认文件存在、可打开/可编辑；
- 脚本任务：实际运行并报告退出码/关键输出；
- 飞书推送：确认 Feishu `code=0` / `msg=success`；
- 定时任务：确认 cron 配置、脚本路径、skills 绑定；
- 文档材料：确认格式、路径、核心内容符合用户偏好。

## 输出风格

- 默认简体中文；
- 面向办公场景时，优先“可直接使用”；
- 面向领导/飞书/简报时，简洁、有判断、有数据、有链接；
- 面向配置/脚本时，报告做了什么、验证结果、后续注意点；
- 不把内部长日志原样倾倒给用户。

## 典型维护场景：Hermes 系统性健康检查

当用户长时间未使用后回来，或主动要求"检查有什么需要更新的"，执行以下系统性检查流程：

### 检查清单

1. **版本检查**：`hermes --version` — 确认是否最新
2. **Config 检查**（主 profile + 所有子 profile）：
   - 主 config 须用 CLI 修改（`hermes config set display.language zh`），patch 被安全限制阻止
   - 子 profile config（profiles/office/review/think/config.yaml）可直接用 patch 修改
   - 检查项：`display.language`、`display.personality`、其他可能过时的默认值
3. **Cron 任务检查**：`cronjob(action='list')`
   - 检查名称是否带"试运行"等临时标记，如有则更新
   - 检查 deliver 渠道（local 不推送，改为平台渠道如 `feishu:oc_<chat_id>`；chat_id 从 `~/.hermes/channel_directory.json` 获取，只需群聊 `oc_` 开头的 ID，勿用 `cli_` 开头的 bot app ID）
   - 检查 prompt 是否仍引用临时说明
4. **记忆空间压缩**：`memory(action='add')` 失败时（已达上限），用 `operations` 数组一次完成多个 replace/remove，压缩后目标 < 50%
5. **Skills 检查**：`skills_list()` 确认关键技能都在
6. **结论汇总**：按配置 / cron / 记忆 / 其他分类报告

### 注意事项

- 主 config.yaml 不能直接用 patch 修改（安全限制），必须用 `hermes config set` CLI
- 子 profile config 可以 patch 直接改
- 记忆压缩时，用户偏好（党建发言偏好等）保留不变，只压缩技术细节和过时内容
- Cron deliver 改为平台渠道后，输出会推送到对应平台而非留在本地

## 典型验收句式

完成后简洁报告：

```text
已启用/已修改：...
验证结果：...
后续默认口径：...
需要你观察/反馈的点：...
```
