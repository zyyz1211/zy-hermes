# 台账统计 Excel 工作簿

按「分组维度 × 分类」统计条数与金额合计，输出可直接交付的工作簿。
典型请求："各企业在 X/Y/Z 分类下分别多少项目、合计多少金额，弄成 Excel 方便查看"。

## 触发条件

- 台账/清单按某列分类汇总（计数 + 金额合计）
- 输出 Excel 工作簿供查看/上报
- 合同台账、项目进展、月度统计类任务

## 工作流

### 1. 先摸结构，别急着算
读 sheet 名、表头、行数；对「分类列」跑 `collections.Counter` 枚举全部唯一值——这是最重要的一步：
- 用户口中的分类名 ≠ 单元格里的原始值。实测案例：用户说"一审/二审/仲裁"，表里是"一审中/二审中/结算仲裁"。先枚举唯一值，再建立 原始值→目标分类 映射，映射口径要在汇报里写明。
- 顺带发现拼写变体（多余空格、全半角）和意外取值。

### 2. 数据质量检查（计算前）
- 金额列：空值/None、非数字文本、负数。空金额行 = 项目数计入、金额按 0，**必须单独列出上报**并输出「待补充清单」，否则金额合计会误导领导。
- 序号列：是否连续无重复（1..N == 数据行数）。
- 分类列：是否全部落入映射。

### 3. 统计口径
- count + amount 按 分组维度×分类 聚合；金额有小数的场景用 Decimal 累加或 round 到 2 位，避免裸 float 加总误差。
- 校验恒等式：各分组行合计 == 分类合计 == 总计；数据行数 == 全部 count 之和。三项对上再交付。

### 4. 三sheet 工作簿
模板脚本：`scripts/ledger_stats_workbook.py`（改 CONFIG 即可跑）。
- **统计汇总**：分组×分类的「项目数」「合同额」分成两列（不要把 "16/205,545.00" 混写进一列——列宽不足会黏连且不便筛选排序）；标题注明金额单位；合计行加粗+底色；底部红字注明数据缺陷口径（如"一审45项中含6项无金额，实为39项有金额"）。
- **明细**：原始逐行数据 + 映射后分类列 + 异常标记列；异常行黄色高亮；冻结首行；金额列 number_format='#,##0.00'。
- **待补充清单**：只列缺金额/异常行，格式可直接转发业务方回填。

### 5. 验证
生成后重新用 openpyxl 读回：sheet 名、行数、合计行数字、待补充清单条数，逐项比对后再交付。交付时给出文件绝对路径。

### 6. 独立复核（数据准确性类任务的标配动作）
用户对数据准确性极其重视，常直接要求"来一个子 agent 审核你的输出"。派 leaf 子 agent 独立重算，context 传三样：原始数据文件路径 + 结果 JSON 路径 + 分类映射约定；goal 明确写"从原始数据独立重算，不要读主 agent 的统计脚本（只允许读结果文件做对比）"。审核清单固定四项：a) 分类列有无映射外取值；b) 金额有无空值/非数字；c) 小数金额加总精度（用 Decimal）；d) 行数全部归入且无重复。要求输出结构化中文报告（审核结论/差异明细/检查项结果/最终确认数据）。子 agent 报告里的关键断言（如"发现6行空金额"）主 agent 必须亲自重读原始表核实后才采信——子 agent 自述不可全信。

## 脚本规范（用户）
- 脚本统一存 `Desktop\09_工具脚本\`，不散放桌面
- `# -*- coding: utf-8 -*-`，`open(encoding='utf-8')`
- 统计结果 JSON 与 xlsx 同目录保存，供子 agent 复核对比

## 坑
- 表内状态值常是用户分类名的近义变体（一审中 vs 一审），先 Counter 枚举再映射，别硬编码猜测。
- 空金额行静默按 0 计入会让合计金额偏小——必须在交付物里显式标注，不能只在小字里提。
- 终端打印宽表时列宽不足数字会黏连（实测合计行 "12" 与 "85702.79" 黏在一起），终端输出用固定列宽，交付以 xlsx 为准。
- 生成脚本第一次跑挂是常态（列索引/变量名笔误），跑完必须重读文件验证，不能只看脚本无报错。
