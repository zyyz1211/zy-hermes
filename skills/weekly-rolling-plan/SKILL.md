# 周滚动计划生成

用户用户使用固定的周滚动计划 Excel 模版，每次生成时替换日期、星期和内容。

## 触发条件

用户说"写周报"、"周滚动计划"、"本周总结"、提供工作总结内容时触发。
此外，当用户需要处理、整理、清洗、合并 Excel 文件（如客户商机信息表、项目清单等），要求"合并同一项目"、"整理数据"等时，也适用本技能提供的 openpyxl 工具链。

## 模版格式（精确样式）

基于 周滚动计划_第19周.xlsx 分析：

| 单元格 | 内容 | 字体 | 字号 | 加粗 | 对齐 | 行高 |
|--------|------|------|------|------|------|------|
| A1:A2（合并） | 某工程集团经营管理部\n周滚动计划 | 宋体 | 20 | 是 | 居中/居中/自动换行 | A1=34, A2=48 |
| A3 | 姓名：用户 第{N}周 {开始日期}至{结束日期} | 宋体 | 16 | 是 | 居中/居中 | 30 |
| A4 | 本周总结： | 黑体 | 12 | 是 | 左/居中 | 24 |
| A5~A9 | 本周总结内容（一、二、三、四、五） | 宋体 | 12 | 否 | 左/居中/自动换行 | 30 |
| A11 | 下周工作重点： | 黑体 | 12 | 是 | 左/居中 | 24 |
| A12~A17 | 下周计划（每天标题+子项） | 宋体 | 12 | 否 | 左/居中/自动换行 | 内容量*15，最低30 |

**列宽：** A列 = 95（足够容纳长文本）
**日期格式：** `2026年05月11日至2026年05月17日`

## 下周计划格式

每天格式为：
```
一、6月1日 周一：
  1.任务1。
  2.任务2。
```

编号统一用中文数字（一、二、三、四、五、六），星期用中文（周一至周日）。
周末（周六-周日）可合并为一项。

## 内容规划——双主线模式

用户的工作节奏通常围绕两条主线展开，生成内容时优先按此框架填充：

**主线一：签约抢位**
- 某大型能源集团（供应商入库、评标专家推荐、材料汇总）
- 央企客户高层拜访（中国石化、国家能源、某央企电力集团、某央企军工集团等——公函流转、行程协调）
- 签约项目清单梳理（节点确认、责任人跟进）

**主线二：半年度汇报起跑 / 总结汇报**
- 经济活动分析会 PPT
- 半年度经营工作总结框架搭建
- 部门工作布置会材料
- 战略合作协议台账更新
- 重点项目进展跟踪
- 客户拜访完成情况梳理

**日常持续事项：**
- 客户商机信息表更新与清洗（某化纤集团、某石化企业、某能源集团等）
- 部门临时交办任务
- 拜访函件、战略合作备忘录等日常公文

## ⚠️ 内容深度要求——避免"太简单"反馈

**用户曾明确反馈"细化细化，怎么感觉你写的这么简单呢"，这是内容深度不足的硬信号。**  
周报内容绝不能写空洞的泛泛描述。每次填充内容时，必须遵循以下细化规则：

### 每条内容都要"有血有肉"

**本周总结的5条**和**下周计划每天3-5条**，每条必须包含以下要素的至少3项：

1. **可量化的数字**：搜集了多少份文件、对比了几种路线、多少字的报告、多少在库客户、几个项目更新了状态
2. **具体的文件/政策名称**：政策文件写全称（如《关于推动现代煤化工产业健康发展的通知》），不要写"相关政策"
3. **具体的部门/人员**：对接了哪些部门（财务部、技术管理部、市场开发部），报送了哪位领导（代部长、分管领导）
4. **具体的框架/结构**：报告按哪几章结构推进（七章框架）、台账有哪些字段、周报按什么格式组织
5. **具体的动作与产出物**：不写"推进撰写"，写"完成行业政策环境章节初稿约1500字"；不写"跟进客户"，写"重点跟踪某大型能源集团供应商入库（已进入资料补充阶段）"
6. **分析与判断**：识别出几个增长点、标注几个项目滞后及原因、提出什么建议

### 对比示例

| ❌ 太简单（会被打回） | ✅ 细化版（通过） |
|------|---------------------|
| "搜集了相关政策文件" | "系统搜集了国家发改委2025-2026年现代煤化工产业政策文件5份（含《煤制油产业布局指导意见》等）" |
| "对比了不同技术路线" | "对比分析3种主流工艺路线（费托合成、直接液化、甲醇制汽油）的经济性指标" |
| "制作了项目表格" | "制作项目进展表格清单（含项目名称、阶段、投资额、产能规模、责任单位等字段）" |
| "推进报告撰写" | "完成行业政策环境与市场分析章节撰写，形成约1500字初稿" |
| "对接相关部门" | "对接财务部（收集IRR、投资回收期等参数）、技术管理部（获取单位产品投资额指标）" |

### 下周计划每天条数

- 工作日（周一至周五）：每天 **3-5条** 任务，每条约40-80字，含具体动作+产出物
- 周末：**1-2条**（梳理/准备类）
- 任务不能写成"推进XX"一句话，必须展开说清楚做什么、怎么做、产出什么

### 深度自检（生成后必查）

- [ ] 每条总结/计划是否至少包含1个量化数据？
- [ ] 政策文件是否写全名而非"相关政策"？
- [ ] 客户/合作方是否写全称？
- [ ] 是否标注了涉及的具体部门？
- [ ] 是否有"做了什么事→具体内容→产出什么→影响/结果"的完整叙事？
- [ ] 下周计划每条任务是否有明确的产出物描述？

详细深度标准与更多示例见 `references/周报内容深度标准与示例.md`。

## 核心原则：零确认、直接干

用户已授权"直接执行，不用中断询问"。以下所有步骤都不需要停下来问用户确认。

## 执行步骤

1. 根据当前日期确定周数，计算下周起止日期（周一至周日）
   - **周数计算规则：** 周报的标题"第{N}周"必须与日期范围对齐。如果日期范围是 6月1日~6月7日，则周数应使用该日期范围的 ISO 周数。用 Python `datetime.date(2026, 6, 1).isocalendar()[1]` 计算，结果为 23，不是 22。
   - ❌ 不要硬编码 `WEEKNO = 22` 然后用 6月1日~7日（ISO 23周）的日期范围
   - ❌ 如果仅因为脚本中的计算基准日期在 ISO 第22周，就将下周（实际第23周）也标注为第22周
   - ✅ 正确做法：根据下周的日期范围（6月1日~7日）计算实际周数：`may29 + timedelta(days=...).isocalendar()[1]`
2. **一次性**问用户要所有信息：本周总结内容 + 下周工作内容。只用一问，不要分批，不要逐条确认
3. 如果用户已提供 think 方案文件且文件路径已知，尝试读取作为内容参考
   - 如果文件不存在，根据双主线框架 + 历史会话上下文自行构建合理内容
4. 用 openpyxl 创建 Excel，按模版格式填入
5. 同时生成 Markdown 备忘文件
6. 保存到指定路径，直接告知结果
7. 不需要问"是否满意"、"要不要改"——用户有需要会自己说

## Python 执行环境（重要）

WSL 内 `/usr/bin/python3` 通常没有安装 openpyxl。**不要用 WSL Python 运行 Excel 脚本。**

可使用以下任一 Windows Python 环境（已验证均有 openpyxl）：

| 环境 | 路径 |
|------|------|
| Hermes venv（推荐） | `/mnt/c/Users/<user>/.hermes/hermes-agent/.venv/Scripts/python.exe` |
| Windows Python 系统安装 | `/mnt/c/Users/<user>/AppData/Local/Programs/Python/Python313/python.exe` |

### 可靠执行方式（已验证）

**方式 A（推荐——管道输入，避免 MSYS 路径乱码）：**
把脚本写到 WSL 原生路径（如 /home/administrator/），然后通过 stdin 管道执行：
```
/mnt/c/Users/<user>/.hermes/hermes-agent/.venv/Scripts/python.exe < /home/administrator/gen_script.py
```

**方式 B（cmd.exe 包装）：**
```
cmd.exe /c "C:\Users\<user>\.hermes\hermes-agent\.venv\Scripts\python.exe C:\path\to\script.py"
```

### 已知坑（必须避免）

- **不要**直接用 WSL bash 调用 Windows Python + Windows 路径参数：`/mnt/c/.../python.exe C:\\path\\script.py` 会因为 MSYS 把反斜杠转义而导致 `File Not Found`
- **不要**用 write_file 写脚本到 `C:\\...` 路径后依赖 WSL 读取——write_file 在 Windows 环境下会创建字面量目录结构（如 `/mnt/c/Users/<user>/C:\Users\...`），文件实际不在桌面。write_file 的 Windows 路径在 WSL 下不可靠
- 可靠的脚本存放方式：用 `write_file` 写到 `/home/administrator/`（WSL 原生路径），一定能读取到
- **read_file 在 WSL 下不可读 Windows 桌面文件：** `read_file(C:\Users\<user>\Desktop\...)` 会失败，提示 `No such file or directory`。改用 `cat /mnt/c/Users/<user>/Desktop/...` 或 Windows Python 读取

## Excel 通用数据处理模式

当需要"合并同一项目"、"清洗/整理 Excel 数据"、"按大类分组"时，参考以下模式：

1. 用 openpyxl 读取原始 Excel，解析表头和数据结构
2. 识别"大项目/父项目"的分组规则（关键词匹配、业主名称、项目名称前缀等）
3. 同一大项目下的多条子项合并为组，但**总投资额取大项目的正确值，不累加**
4. 每个子项单独保留：合同额、所属公司、投标月份、项目概况等细节
5. 输出新 Excel，用颜色交替区分不同大项目组，冻结首行

## 注意事项（根据实际使用积累）

- **路径核实**：用户桌面目录经反复整理，以实际 `cmd.exe /c "dir ..."` 输出的结构为准，不要用技能里硬编码的老路径
- A列宽度 95 足够容纳长文本
- A1 和 A3 需要加粗
- 日期和星期必须与实际日历对应
- **第N周**：如果用户指定了周数，直接使用；如果未指定，根据 ISO 日历计算。**周数与日期范围必须一致。** 例：6月1日~7日的周数用 `datetime.date(2026, 6, 1).isocalendar()[1]` 计算 = 23，不可用当前日期（5月29日）的周数 22 代替
- 从参考模版文件中读取样式（字体、字号、对齐方式、行高、列宽等）后直接套用，不要问用户"这样格式行不行"
- 日期和星期由程序自动计算，不要问用户"这周是不是第X周"
- **think 方案缺失**：如果用户说读取 think 方案但文件不存在，根据已有的工作上下文（某大型能源集团、央企客户、半年度汇报等）自行构建合理内容，不要停下来报告"文件不存在"耽误进度
- **内容深度不是可选项**：用户的历史反馈模式是先给粗版 -> 看了说太简单 -> 要求细化。不要等用户说"细化"才加细节。首次输出就按上面的深度标准写到位，一次通过。宁可写太细、不要写太粗。参考对比示例表，确保每条总结/计划含具体名称+量化数字+部门/人员+产出物。

## 生成后审核

生成周报 Excel + 备忘后，建议执行以下自检：

### 🔴 严重检查（信息准确）
- [ ] 周数编号与日期范围是否一致？（ISO 校准：`datetime.date(范围日期).isocalendar()[1]`）
- [ ] "本周总结"的内容时间范围是否明确标注？
- [ ] 客户/项目名称是否有笔误？

### 🟡 一般检查（逻辑清晰）
- [ ] "本周""下周"指代是否清晰无歧义？
- [ ] 计划量与历史周报相比是否合理？
- [ ] 主线分类（签约抢位/半年度汇报）是否覆盖了全部事项？

### 🟢 建议检查（格式与深度）
- [ ] Excel 除 A 列外是否需要扩展（优先级/责任人/状态列）？
- [ ] 备忘文件的"日常持续事项"是否足够具体？
- [ ] 上周计划完成情况是否有关联跟踪？
- [ ] 每条内容是否包含量化数字、具体名称、具体部门、具体动作中的至少3项？（详见"内容深度要求"节和 references/周报内容深度标准与示例.md）
