# 周滚动计划 — 审核清单

对用户每周产出的周报 Excel + 备忘文件进行审核时，按以下清单逐项检查。

---

## 一、🔴 严重问题（信息准确性）

| 检查项 | 方法 | 预期 |
|--------|------|------|
| **周数编号正确** | 用 Python 验证：`datetime.date(日期).isocalendar()[1]` | 标题周数 = 日期范围的实际 ISO 周数 |
| **日期范围正确** | 周一~周日，与实际日历对齐 | Excel + 备忘一致 |
| **"本周总结"时间标注** | 确认"本周总结"内容的实际时间范围是否在表头中体现 | 读者不产生时间混乱 |
| **客户/项目名称准确** | 交叉检查历史周报、聊天记录中的名称 | 无错别字、无张冠李戴 |
| **备忘录数据与Excel一致** | 对比备忘录内容与Excel内容 | 无矛盾信息 |

### 典型错误案例

| 错误 | 后果 | 发现方式 |
|------|------|---------|
| 周数=22，日期范围=6/1~6/7（实际23周） | 上级核查时发现编号不一致 | ISO 计算 `(2026,6,1).isocalendar()` = 23 |
| "本周总结"内容为5月工作，表头日期为6月 | 读者无法判断"本周"到底指哪一周 | 标注"第22周(5/25~5/29)工作回顾" |

---

## 二、🟡 一般问题（逻辑与表达）

| 检查项 | 说明 |
|--------|------|
| **"本周""下周"指代清晰** | 如果周一任务是"梳理本周签约项目"，周一当天尚无可梳理的"本周"内容 |
| **任务描述可验收** | 是否可回答"做完了吗？"（如"完成初稿"优于"编制"） |
| **计划量与历史对比合理** | 和工作量是否符合用户日常节奏 |
| **双主线分类覆盖全面** | 主线一（签约抢位）+ 主线二（半年度汇报）+ 日常，是否涵盖所有事项 |
| **与上周计划关联** | 上周未完成的事项是否在本周有跟进 |

---

## 三、🟢 建议改进（格式与完整性）

| 检查项 | 说明 |
|--------|------|
| **Excel 扩展列** | 是否增加优先级/责任人/状态列提升可追踪性 |
| **备忘"日常事项"具体化** | 是否过于泛泛（"部门临时交办任务"→改为具体事项或删除） |
| **需协调事项** | 是否有"需领导协调"的单独字段 |
| **上周完成度标记** | 是否有对上周计划完成情况的追踪（已完成/延期/取消） |
| **一致性检查** | Excel 与备忘中同事项的描述是否一致 |

---
